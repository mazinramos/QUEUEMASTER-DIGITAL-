# الحساب 5 — المرحلة 5: الأدمن الجديد، المثبّت، العرض التجريبي، وثائق البيع
**الفرع:** `acct-5-admin-qa`  |  **المايجريشن:** 008
**أنجز أولاً:** تقريرك النهائي للمراحل السابقة، وإصلاح اختبار `ads.integration.test.js` الذي يعطي 404 على `/media` (الراجح أن الاختبار يمرر uploadsDir مختلفاً عن إعداد الخادم، فوحّد الاعتماد على `config.uploadsDir` أو مرّره للـ media handler).

## قبل أي شيء
1. أنهِ مهامك الحالية العالقة (مذكورة تحت) ثم ابدأ هذا الملف. التقرير عن كل ما سبق يُرفع أولاً.
2. `git fetch` وادمج `origin/main` في فرعك. هذا ملف المرحلة 5: **بيع المشروع كمنتج تجاري**.
3. اقرأ بالترتيب: `docs/DESIGN-BRIEF.md` (ملزم، ويُراجَع بصرياً)، `docs/phase5-contract.md` (عقد ملزم)، `docs/COMMERCIAL-ROADMAP.md`، `docs/workflow.md`.
4. شغّل `node supervisor/design-lint.js` قبل كل PR: لا يُقبل التسليم مع FAIL.
5. لا تعدّل ملفات حساب آخر. إن احتجت تغييراً عنده، اكتبه في تقريرك. أرقام المايجريشن محجوزة في العقد.
6. كل ما تدّعيه "مختبر" يجب أن يكون جرّبته فعلاً، وما لا يمكن تجربته هنا اذكره في "ما لم يُجرَّب".
7. التقرير النهائي: `reports/acct-N/` بنفس القالب، ولقطات الشاشة حسب بند 8 في دليل التصميم.

## المهام (بالأولوية)
### أ. لوحة الأدمن بالتصميم الجديد
أعد بناء `web/admin/` على نظام التصميم الجديد من حساب 3 (انتظر أول PR له، وابدأ بالهيكل والتنقل). شاشات الإعدادات الجديدة: وضع تدفق الموظف، مهلة "لم يحضر"، التنبيه المبكر، العلامة التجارية (شعار، لون مع معاينة حية للتذكرة وللشاشة)، خريطة نطق الحروف مع زر تجربة نطق، الترخيص (الحالة والرفع)، النسخ الاحتياطي (من مسارات ح1)، وصفحة "إثبات عرض الإعلانات" (جدول ورسم بسيط وتصدير CSV) و"محاولات التحقق الفاشلة". لوحة المعلومات الرئيسية بتصميم هادئ بلا بطاقات ملونة.
### ب. إثبات العرض والتقارير
`GET /api/admin/ads/stats` و`GET /api/admin/verify-failures` كما في العقد، واختبارات. مايجريشن `008` فقط إن احتجت جدولاً (وإلا لا).
### ج. مثبّت Windows (أولوية البيع)
- `scripts/windows/`: سكربت PowerShell يثبّت Node المطلوب (إصدار مثبّت ومحزّم أو تنزيل موثق)، ينسخ التطبيق، يشغّل `npm ci`، يولّد الأسرار، ينشئ المستخدم الأول، يضبط **خدمة Windows** (NSSM أو `node-windows`) تبدأ تلقائياً وتعيد التشغيل عند الفشل، ويضيف قاعدة جدار ناري، ويضع اختصارات: لوحة الموظف، الأدمن، الشاشة بوضع kiosk (Chrome/Edge)، ويحجز IP ثابتاً (توجيه). وسكربت إزالة وسكربت ترقية يحافظ على البيانات ويأخذ نسخة قبل التحديث.
- (اختياري إن أمكن) مثبّت `.exe` عبر Inno Setup يغلّف ما سبق.
- **ما لم تستطع تجربته على Windows فعلاً اذكره بصراحة** واكتب قائمة تحقق يدوية لصاحب المشروع.
- `docs/https-local.md` (من ح1) مدمج كخطوة اختيارية في المثبّت.
### د. وضع العرض التجريبي (Demo)
`npm run seed:demo`: عيادة نموذجية واقعية (شعار، خدمات، موظفون، إعلانات صور، بيانات سابقة لتقارير ممتلئة)، ومحاكي حركة `npm run demo:traffic` يُصدر تذاكر وينادي تلقائياً بإيقاع واقعي لتبدو الشاشات حيّة في العرض لعميل. يرفض التشغيل في الإنتاج، ويظهر شريط "عرض تجريبي".
### هـ. القياس والاختبار البصري
سكربت `scripts/qa/screens.js` بمتصفح حقيقي يلتقط كل الشاشات بالأحجام في دليل التصميم (عربي/إنجليزي) ويحفظها في `reports/acct-5/screens/`، يشمل صفحات ح3 وح4 أيضاً (ليستخدمه المشرف في المراجعة)، وتشغيل `design-lint` ضمن `npm test` للويب كتحذير يتحول إلى فشل لاحقاً.
### و. وثائق البيع والتشغيل (`docs/sales/` و`docs/`)
- `installation.md` (Windows 11 خطوة بخطوة بلقطات)، `network-setup.md` (راوتر، شبكة ضيوف، عزل العملاء، IP ثابت، جدار ناري، بدون افتراض راوتر معين)، `backup-restore.md`، `security.md`، `user-guide.md` (مريض/موظف/أدمن)، `clinic-install-checklist.md`، `KNOWN-LIMITATIONS.md`، `TEST-REPORT.md` بثلاثة أقسام (مختبر / يحتاج credentials / غير منفذ).
- `docs/sales/`: `pitch.md` (عرض تعريفي بهيكل الشرائح)، `pricing-model.md` (نموذج تسعير مقترح مع افتراضات صريحة ومقارنة بخدمات الطوابير الورقية)، `sla-template.md`، `privacy-policy-template.md`، `eula-template.md` (قوالب، وتنبيه أنها ليست استشارة قانونية)، `hardware-guide.md` (جهاز الخادم، الراوتر، الشاشة، التركيب)، `demo-script.md` (سيناريو عرض 10 دقائق).
- `LICENSE` مناسب للبيع (مملوك، ليس مفتوح المصدر) بعد موافقة صاحب المشروع، وتذكير بتحويل الريبو Private.

## قبول
المثبّت مجرَّب بقدر الإمكان مع قائمة تحقق Windows صريحة، العرض التجريبي يعمل، اللقطات الشاملة مرفوعة، `design-lint` أخضر على الأدمن، وتقرير شامل.
