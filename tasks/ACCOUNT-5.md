# الحساب 5 — الأدمن والإعلانات والتقارير والاختبارات والتوثيق
**الفرع:** `acct-5-admin-qa`  |  ابدأ بالتوثيق واختبارات التكامل المبكرة، ثم لوحة الأدمن بعدما تجهز واجهات حساب 1 و2.

## قبل أي شيء
1. اقرأ بالترتيب: `README.md`، `docs/SPEC-SUMMARY.md`، `docs/workflow.md`، `docs/architecture.md`، `docs/database.md`، `docs/api-contract.md`، `docs/socket-events.md`.
2. اعمل على فرعك فقط، وفي ملفاتك فقط (جدول الملكية في `architecture.md`).
3. نفّذ ملفات حقيقية واختبرها فعلياً. لا أزرار وهمية، ولا إعلان اكتمال قبل الاختبار.
4. ارفع شغلك على فرعك باستمرار، وافتح Pull Request نحو `main` عند كل مرحلة، وأضف تقريراً في `reports/acct-N/` من `reports/TEMPLATE.md`.
5. البيئة: Node 20+، Windows 11 هو هدف الاختبار (مسارات متوافقة، لا أوامر bash فقط في scripts؛ وفّر بدائل npm scripts).

## المهام
### المرحلة 1: الإعلانات (باك إند) + هيكل الاختبارات
- `routes/ads.js` + `services/ads*.js`: رفع آمن (multer): أنواع JPG/PNG/WebP/MP4 بفحص الـ magic bytes لا الامتداد فقط، حجم أقصى، أسماء ملفات عشوائية، CRUD كامل، جدولة، أولوية، استهداف شاشات، معاينة، وبث `advertisement:updated` عبر `emitToClinic`.
- `server/tests/`: بنية الاختبارات، أدوات مساعدة (إنشاء DB مؤقتة، تسجيل دخول)، سكربت `npm test`.
### المرحلة 2: لوحة الأدمن `web/admin/`
- بطاقات الإحصاءات (اليوم، المنتظرون، قيد الخدمة، المكتملة، المتخطاة، الملغاة، متوسط الانتظار، متوسط الخدمة)، أداء الخدمات والشبابيك، رسوم بيانية يومية/أسبوعية بـ SVG/Canvas بسيط بلا مكتبات خارجية.
- شاشات: العيادة، الخدمات، الشبابيك، الموظفون، الطابور (بحث/تصفية/سجل أحداث/إلغاء/تصحيح بتسجيل تدقيق/تصفير يومي بتأكيد)، الإعلانات (رفع، تعديل، معاينة)، إعدادات الشاشات والصوت، المزامنة وSMS (حالة).
- تصميم احترافي RTL/LTR باستخدام `web/shared` من حساب 3.
### المرحلة 3: التقارير
- `routes/reports.js`: يومي/أسبوعي/شهري، أداء الخدمات، أوقات الانتظار، أداء الموظفين، تصدير CSV (بترميز UTF-8 مع BOM ليفتح العربي في Excel)، وصفحات طباعة.
### المرحلة 4: التوثيق والاختبار الشامل والتسليم
- `docs/`: installation.md (Windows 11 خطوة بخطوة، تشغيل كخدمة)، network-setup.md (Wi-Fi الضيوف، client isolation، قواعد جدار الحماية، IP ثابت، DNS محلي، لا افتراض لراوتر معين)، database.md (مضاف)، security.md، user-guide.md (مريض/موظف/أدمن)، admin-setup.md، backup-restore.md، clinic-install-checklist.md، TEST-REPORT.md، KNOWN-LIMITATIONS.md.
- اختبارات شاملة: تزامن، offline وإعادة تشغيل السيرفر، أمان (SQLi/XSS/رفع ملفات/CSRF/rate limit)، أداء بسيط. التقرير النهائي بثلاثة أقسام: منفذ ومختبر / يحتاج credentials / غير منفذ.
- سكربتات `scripts/`: backup وrestore وتشغيل على Windows.

### قبول
كل ما في التوثيق مجرّب فعلياً. لا تدّعي نجاح SMS أو Firebase بدون credentials؛ وثّق المطلوب بالضبط.
