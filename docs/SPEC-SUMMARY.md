# ملخص المتطلبات (SPEC SUMMARY)

> النص الكامل للمواصفات: ضع ملف المواصفات الأصلي في `docs/MASTER_PROMPT.md`. عند أي تعارض يُرجع للنص الكامل.

## المبادئ
بدون طابعات حرارية، ESP32، أو أجهزة. المريض بهاتفه عبر Wi-Fi العيادة. السيرفر المحلي هو المرجع، وFirebase اختياري ولا يُعتمد عليه للإصدار أو النداء. دعم عدة عيادات (multi-clinic) مع عزل بيانات صارم.

## التقنية
Backend: Node.js, Express, SQLite (better-sqlite3 موصى به), Socket.IO, Zod, bcrypt/Argon2, جلسات آمنة.
Frontend: HTML/CSS/JS خام (ES6+) + Socket.IO client. بدون frameworks أو build tools.

## الواجهات
1. `/patient` بوابة المريض (عربي افتراضي + إنجليزي، تذكرة رقمية، QR، حفظ صورة/PDF، مشاركة، SMS اختياري، استرجاع التذكرة)
2. `/staff` لوحة الموظف (نداء، إعادة نداء، بدء، إنهاء، تخطي، إرجاع، إلغاء، تحقق بالرقم/QR، تحويل)
3. `/admin` لوحة الأدمن (إحصائيات، عيادة، خدمات، شبابيك، موظفين، تذاكر، تقارير CSV، إعلانات)
4. `/display` شاشة الانتظار: قسم الطابور دائماً ظاهر + قسم إعلانات متناوب + صوت

## قواعد الطابور
- الترقيم يتولد في الباك إند داخل transaction، يتصفر يومياً حسب منطقة العيادة، لكل خدمة بادئة (A-001).
- التذكرة المنتظرة فقط يمكن نداؤها، ولا يمكن لموظفين نداء نفس التذكرة.
- كل إجراء يُسجل في ticket_events و audit_logs.
- توكن QR عشوائي آمن، يُخزن hash فقط (SHA-256).

## الصوت
Web Speech API مع خيارات: اللغة (ar/en/both)، السرعة، النبرة، الصوت، التكرار، التأخير. زر "تفعيل الصوت" عند حظر autoplay. طابور نداءات بلا تداخل. تشغيل الصوت من أحداث السيرفر فقط.

## الأمان
Hash لكلمات المرور، جلسات + RBAC، Zod، rate limiting، CSRF، XSS، رفع ملفات آمن، لا أسرار في Git، لا كلمات مرور افتراضية للإنتاج.

## قاعدة الصدق
لا يُعلن عن ميزة أنها مكتملة قبل اختبارها فعلياً. التقارير تفرّق بين: (أ) منفذ ومختبر، (ب) منفذ ويحتاج credentials، (ج) غير منفذ.
